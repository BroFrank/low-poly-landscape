# Plan.md — план разработки Low Poly Landscape

> Этот файл — единственный источник порядка работ.
> Статусы: `- [ ]` не начато · `- [~]` в работе · `- [x]` выполнено и подтверждено юзером.
> Менять статусы может только `orchestrator`.

**Цель:** веб-приложение (SPA) для ландшафтного дизайна в low-poly стиле на `three.js`:
редактирование рельефа, кисти покрытий, расстановка объектов, свободная камера, день/ночь, скриншоты, сохранение сцены.

**Стек:** TypeScript (strict) + Vite + `three`.

---

## Этап 0. Фундамент проекта

### - [x] **T001 — Каркас проекта**
- Создать `package.json` (`three`, `typescript`, `vite`, `@types/three`), `tsconfig.json` (strict), `index.html`, `src/main.ts`.
- Скрипты: `dev`, `build`, `preview`.
- `.gitignore` (`node_modules`, `dist`, `.opencode/state`).
- **DoD:** `npm install`, `npm run dev` открывает страницу с `<canvas>` во всю площадь окна; `npm run build` проходит.
- **Проверка юзером:** запустить `npm run dev`, открыть браузер — виден пустой холст без ошибок в консоли.

### - [x] **T002 — Ядро сцены и камера**
- `core/scene.ts`: `Scene`, `WebGLRenderer` (антиалиасинг, DPR), обработка resize.
- `core/camera.ts`: `PerspectiveCamera` + `OrbitControls` (rotate/pan/zoom) + свободное движение WASD (pan), `Q`/`E` (подъём/опускание), `R` — сброс вида.
- Тестовая сцена: плоский квадратный ландшафт 100×100 с травяным цветом и сетка-подложка.
- **DoD:** камера свободно вращается, панорамируется и двигается; ограничения не мешают облету территории.
- **Проверка юзером:** покрутить камеру мышью и WASD, убедиться, что видно квадратный зелёный ландшафт.

### - [x] **T003 — UI-оболочка**
- `ui/toolbar.ts`: панель инструментов (Высота вверх/вниз, Камень, Земля, Объекты, Сброс, Скриншот, День/Ночь).
- `ui/hud.ts`: строка статуса (текущий инструмент, радиус кисти, количество объектов) + мини-справка горячих клавиш.
- Активный инструмент подсвечивается; режимы переключаются без конфликта.
- **DoD:** UI не перекрывает сцену, корректно работает при resize, выбранный инструмент отражён в статусе.
- **Проверка юзером:** кликнуть по всем кнопкам — статус меняется, ни одна кнопка не «зависает».

## Этап 1. Камера, освещение, окружение

### - [ ] **T004 — Скриншот сцены**
- `core/screenshot.ts`: `renderer.render()` → `canvas.toDataURL('image/png')` → скачивание файла `landscape-<timestamp>.png`.
- Сохранять только область сцены (без UI), в текущем освещении.
- **DoD:** файл корректно открывается, разрешение = размеру окна.
- **Проверка юзером:** нажать «Скриншот», открыть скачанный PNG — видно текущий вид камеры.

### - [ ] **T005 — День и ночь**
- `core/lighting.ts`: направленное «солнце» (тени), полусферический заполняющий свет, цвет фона/неба, туман.
- Режимы: Day / Night / Auto-cycle (полный цикл ~60 с, регулируется).
- Плавный переход (интерполяция intensities и цвета неба), ночные звёзды (точечные спрайты).
- **DoD:** переключение режимов работает, тени обновляются, консоль чистая.
- **Проверка юзером:** переключить Day→Night→Auto, убедиться, что сцена темнеет и свет возвращается плавно.

### - [ ] **T006 — Выбор точки на ландшафте (raycast)**
- `terrain/raycast.ts`: единый helper `getTerrainHit(event) → {x, y, z, gridIndex}`.
- Используется всеми инструментами и расстановкой объектов; игнорировать попадания в объекты.
- **DoD:** при разных углах камеры клик попадает в рельеф, а не «в пустоту».
- **Проверка юзером:** поднять холм, кликнуть на его вершину — координата высоты совпадает с видимой поверхностью.

## Этап 2. Ландшафт и инструменты редактирования

### - [ ] **T007 — Модель рельефа**
- `terrain/terrain.ts`: сетка высот `Float32Array[(GRID+1)²]`, `GRID_SIZE = 64`, площадь 100×100.
- Mesh с вершинными цветами; `getHeight(x, z)` — билинейная интерполяция.
- `setHeight`, `rebuildMesh()`; предельный уклон (без вертикальных стен); границы площади — «обрыв» за пределами.
- **DoD:** рельеф пересчитывается без артефактов; плоская версия совпадает с T002.
- **Проверка юзером:** увидеть плоский квадрат; проверить, что сетка не «ломается» при перестроении.

### - [ ] **T008 — Инструмент «подъём / опускание»**
- `terrain/brushes.ts`: радиус кисти (слайдер 2–20), сила (1–5), профиль Soft/Sharp.
- Подъём — ЛКМ с зажатым инструментом, опускание — Shift+ЛКМ (или отдельная кнопка).
- Drag по поверхности — непрерывное редактирование; мягкий спад по радиусу (cosine).
- **DoD:** рельеф меняется ровно под курсором, нет тряски и «ступеней».
- **Проверка юзером:** нарисовать холм, затем опустить его — форма восстанавливается симметрично.

### - [ ] **T009 — Кисть «каменистый участок»**
- Вершинные цвета в радиусе кисти → `#8f9aa3` / `#6c7580` с лёгкой вариацией.
- Тип покрытия хранится отдельно от высоты (массив `material[]`).
- **DoD:** серый участок сохраняется при последующем изменении высоты.
- **Проверка юзером:** покрасить область камнем, затем поднять её — цвет остаётся серым.

### - [ ] **T010 — Кисть «земля»**
- Аналогично T009, цвета `#7a5c3a` / `#5b4227`.
- **DoD:** кисти не смешиваются некорректно; переходы читаемы.
- **Проверка юзером:** нарисовать участок земли рядом с камнем — видны два разных покрытия.

### - [ ] **T011 — Сброс**
- Кнопка «Сброс»: удаляет все объекты, обнуляет высоты, возвращает травяное покрытие.
- Подтверждение через простой диалог (`confirm`) перед сбросом.
- **DoD:** сцена полностью возвращается к состоянию по умолчанию.
- **Проверка юзером:** разместить объекты и холмы, нажать «Сброс» — всё чисто и плоское.

## Этап 3. Объекты

### - [ ] **T012 — Каталог объектов и панель**
- `objects/catalog.ts`: реестр типов по категориям (Каменные, Трава/кусты, Деревья) с метаданными (масштаб, тип модели).
- `ui/palette.ts`: панель с категориями и списком объектов.
- **DoD:** все 9 типов перечислены и выбирают корректную модель-заготовку.
- **Проверка юзером:** открыть панель, увидеть 3 категории и 9 объектов.

### - [ ] **T013 — Привязка к поверхности ландшафта**
- `objects/placement.ts`: при выборе объекта появляется «призрак» на поверхности; клик ставит объект.
- Позиция: `y = terrain.getHeight(x, z)`, объект установлен основанием на поверхность (не в воздухе и не под землёй).
- Объект перепривязывается при последующем редактировании рельефа под ним.
- **DoD:** ни один объект не «парит» и не «утонул» после изменения высоты.
- **Проверка юзером:** поставить дерево, поднять холм под ним — дерево следует за рельефом.

### - [ ] **T014 — Выделение, перемещение, удаление**
- Клик по объекту → рамка/подсветка выделения.
- Перемещение: перетаскивание или стрелки; удаление: `Delete` / кнопка.
- **DoD:** выделение не конфликтует с кистями ландшафта.
- **Проверка юзером:** выделить камень, перетащить, удалить — всё работает, ландшафт не портится.

### - [ ] **T015 — Модели камней**
- `objects/models/stones.ts`:
  - кучка мелких камней (3–5 сплюснутых икосаэдров);
  - средний камень (деформированный додекаэдр);
  - большой булыжник (large icosahedron с фасетированием).
- **DoD:** ≤ 40 треугольников на модель, flat shading, различимы по размеру.
- **Проверка юзером:** разместить все три — видна разница формы и размера.

### - [ ] **T016 — Модели травы и кустов**
- `objects/models/plants.ts`:
  - небольшая область мелкой травы (низкие треугольные «лопасти»);
  - куст ( скопление сегментов);
  - большой кустарник (несколько ветвящихся clusters).
- **DoD:** ≤ 60 треугольников, низкая посадка, читаемый low-poly силуэт.
- **Проверка юзером:** разместить траву на земле — она не торчит и не проваливается.

### - [ ] **T017 — Модели деревьев**
- `objects/models/trees.ts`:
  - **берёза** — светлый тонкий ствол, редкая светлая листва;
  - **дуб** — толстый ствол, широкая плотная крона;
  - **ель** — коническая ярусная хвоя.
- **DoD:** ≤ 120 треугольников на дерево, виды различаются по силуэту.
- **Проверка юзером:** поставить три дерева рядом — различимы без подписей.

## Этап 4. Состояние, производительность, полировка

### - [ ] **T018 — Сохранение и загрузка сцены**
- `storage/schema.ts`: тип `SceneData` (версии, высоты, покрытия, объекты с типом/позицией/масштабом/поворотом).
- `storage/save.ts`: `save()`, `load()`, `clear()`; автосохранение в `localStorage` (debounce 2 с), кнопка «Сохранить».
- **DoD:** после перезагрузки страницы сцена восстанавливается полностью.
- **Проверка юзером:** изменить рельеф, поставить объекты, перезагрузить страницу — всё на месте.

### - [ ] **T019 — Горячие клавиши и справка**
- `1`–`5` выбор инструмента, `G` сетка, `H` справка, `S` скриншот, `D` день/ночь, `Ctrl+S` сохранить, `Delete` удалить выделенное.
- **DoD:** конфликт с клавишами камеры разрешён (WASD остаётся движением).
- **Проверка юзером:** пройтись по списку клавиш, каждая даёт ожидаемый эффект.

### - [ ] **T020 — Производительность и чистота кода**
- Ограничение числа объектов (предупреждение при > 300), переиспользование геометрий, отсутствие утечек (`dispose()` при удалении).
- Нет предупреждений TS, нет неиспользуемых модулей.
- **DoD:** 300 объектов — стабильные ≥ 30 fps.
- **Проверка юзером:** разместить много объектов, покрутить камеру — лагов нет.

### - [ ] **T021 — Документация и финальная проверка**
- Обновить `README.md`: управление, инструменты, команды агента, скриншот.
- Финальная проверка всех функций из раздела «Функционал».
- **DoD:** пользователь, впервые открывший README, способен работать без вопросов.
- **Проверка юзером:** пройтись по полному сценарию: рельеф → кисти → объекты → день/ночь → скриншот → сохранение → сброс.

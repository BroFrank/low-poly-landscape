# AGENTS.md — правила разработки для агентов

Это проект **Low Poly Landscape** — веб-приложение для ландшафтного дизайна на `three.js`.
Все агенты обязаны соблюдать правила ниже. Нарушение правил = невыполненная задача.

## 1. Роли агентов

| Агент | Режим | Обязанность |
|---|---|---|
| `build` | primary | Обычная работа по запросу пользователя вне цикла `next_work`. |
| `orchestrator` | primary | Ведёт цикл разработки: выбирает задачу, делегирует, собирает результат, спрашивает юзера, коммитит. |
| `planner` | subagent | Готовит подробный технический план задачи. **Не редактирует код.** |
| `implementer` | subagent | Пишет код строго по плану. **Не меняет `Plan.md`.** |
| `reviewer` | subagent | Самопроверка диффа: ошибки, регрессии, несоответствие стилю. **Не редактирует код.** |

## 2. Источник истины — `Plan.md`

- Единственный источник порядка работ — `Plan.md`.
- Статусы задач: `- [ ]` не начато, `- [~]` в работе, `- [x]` выполнено и подтверждено юзером.
- Менять статусы в `Plan.md` имеет право **только `orchestrator`**.
- Нельзя выполнять задачу, которая не помечена `[~]` orchestrator'ом, и нельзя закрывать задачу без подтверждения юзера.

## 3. Правила кода

**Стек:** TypeScript (strict), ESM, Vite, `three` (последняя стабильная версия). Новые зависимости — только с явного разрешения.

**Архитектура (не менять без причины):**

```
src/
  main.ts              // точка входа, сборка модулей
  core/
    scene.ts           // Scene, renderer, resize
    camera.ts          // OrbitControls + свободное движение
    lighting.ts        // день/ночь, солнце, небо, тени
    screenshot.ts      //capture PNG
    state.ts           // единое состояние приложения
  terrain/
    terrain.ts         // сетка высот, vertex colors, пересчёт меша
    brushes.ts         // подъём/опускание, кисти камня и земли
    raycast.ts         // выбор точки на ландшафте
  objects/
    catalog.ts         // реестр типов объектов
    models/
      stones.ts        // процедурные low-poly модели камней
      plants.ts        // трава, куст, кустарник
      trees.ts         // берёза, дуб, ель
    placement.ts       // расстановка и «прилипание» к ландшафту
    selection.ts       // выбор, перемещение, удаление
  ui/
    toolbar.ts         // инструменты и кнопки
    palette.ts         // панель объектов
    hud.ts             // подсказки, статус, горячие клавиши
  storage/
    save.ts            // сериализация в JSON + localStorage
    schema.ts          // типы сохранённой сцены
```

**Стиль:**
- Один модуль = одна ответственность. Файл > 300 строк — повод разбить.
- Никаких глобальных переменных; состояние передаётся через `state`/контекст.
- Публичные функции типизированы, `any` запрещён.
- Комментарии на русском, кратко и только там, где логика неочевидна.
- Импорт только `three` из `node_modules`; никаких CDN.

**Стиль визуала (low-poly):**
- `flatShading: true`, плоские грани, без текстур и нормальных карт.
- Цвет — только vertex colors или сплошной цвет материала.
- Палитра фиксирована (см. раздел 6).
- Ограничение на геометрию: камень ≤ 40 треугольников, куст ≤ 60, дерево ≤ 120.

## 4. Правила взаимодействия с ландшафтом

- Ландшафт — сетка `GRID_SIZE = 64` сегментов на стороне, квадрат `100 × 100` единиц.
- Любая точка объекта обязана быть привязана к поверхности: высота берётся из `terrain.getHeight(x, z)`.
- **Запрещено** размещать объекты в воздухе или под поверхностью.
- Изменение высоты не должно создавать вертикальных стен (ограничение уклона).

## 5. Критерий готовности задачи (DoD)

Задача считается готовой только если:

1. `npm run build` проходит без ошибок TypeScript.
2. `npm run dev` запускается, приложение открывается в браузере.
3. Проверка из пункта **«Проверка юзером»** в `Plan.md` пройдена руками.
4. Нет console-ошибок и предупреждений в dev-режиме.
5. `orchestrator` получил явное подтверждение юзера и сделал коммит.

## 7. Git

- Одна подтверждённая задача = один коммит.
- Сообщение коммита: `T012: <короткое описание>` (ID из `Plan.md`).
- Перед коммитом: `git status` и `git diff --stat` — в диффе только файлы задачи.
- Не коммитить: `node_modules/`, `dist/`, `.opencode/state/`, скриншоты из временных папок.

## 8. Чего агентам делать нельзя

- Реализовать функциональность «сверху» задания (незапрошенные фичи).
- Трогать код задач, которые ещё не выполнены.
- Рефакторить вне рамок задачи.
- Отмечать задачу выполненной без ответа юзера.
- Удалять или переписывать `Plan.md` помимо обновления статусов.
